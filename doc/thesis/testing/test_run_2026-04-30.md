## Findings

### Dashboard endpoints are public

The README says all API routes except `/api/auth/*`, `/api/health`, and OpenAPI docs require a JWT. However, these endpoints returned HTTP 200 without authentication:

- `/api/dashboard/summary`
- `/api/dashboard/trend`
- `/api/dashboard/bloom-stats`

Impact: dashboard attempt metrics are exposed anonymously, and the dashboard backend also aggregates all quiz attempts rather than filtering per current user. This is the main issue found in this run.

Recommended fix: add `get_current_user` dependency to dashboard routes and filter queries by `user_id`. For thesis demo, use a clean/demo database and avoid claiming production-grade multi-user analytics isolation until this is fixed.

### Existing direct auth test does not initialize DB

`backend/test_auth.py` failed when run directly against a temporary DB because the tables were not initialized before the first request. The app itself initializes DB on startup, but the test harness does not guarantee that startup path in direct execution.

Recommended fix: wrap `TestClient(app)` in a context manager or call `init_db()` before requests when using a temporary `DATABASE_PATH`.
